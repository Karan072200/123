## 1. What Was Added

### 1.1 Password Security — `backend/security/passwords.py`

- **Argon2id hasher** (`argon2-cffi 25.1`) tuned to ~50-80 ms on Railway CPU
  - `time_cost=2, memory_cost=64 MiB, parallelism=2, hash_len=32, salt_len=16`
- Backward-compatible verify: tries Argon2 first, falls back to bcrypt for
  legacy users
- `password_needs_rehash()` returns True for any bcrypt hash → wired into
  `/api/auth/login` so each successful bcrypt login is transparently
  upgraded to Argon2 (single DB write, hidden from user)
- `validate_password_strength()` policy: length 10–128, ≥3 of 4 character
  classes, deny-list of top-20 common passwords, and ban of email-local-part
  as password. **Note:** the existing Hinglish `validate_password_strength()`
  (Register endpoint) is retained for user-facing errors — the new helper
  is available for future flows that prefer the stricter policy.

### 1.2 Role-Based Access Control — `backend/security/rbac.py` + `backend/routers/rbac.py`

Nine hierarchical roles:

```
SUPER_ADMIN (100)  Emergent staff / backup restore
ADMIN       (90)   Tenant owner
MANAGER     (70)   Almost-owner, no destructive ops
ACCOUNTANT  (55)   All accounting entities + reports
WAREHOUSE   (50)   Warehouses, batches, serials, transfers
FACTORY     (50)   Manufacturing entities
SALES       (50)   Invoices, parties, POS
STAFF       (30)   Limited write (self-scoped)
VIEWER      (10)   Read-only
```

- **Default deny**: `has_permission()` returns False for any permission not
  in the explicit `PERMISSIONS` table.
- **Backward compatible**: users with no `role` field are treated as ADMIN
  of their own ledger — preserves single-tenant behaviour for legacy accounts.
- **Cross-tenant safety**: `/api/rbac/change-role` refuses to modify a user
  outside the caller's `current_ledger_id` unless caller is `SUPER_ADMIN`.

New endpoints:

| Method | Path | Guard |
|---|---|---|
| GET  | `/api/rbac/me`               | any auth |
| GET  | `/api/rbac/roles`            | any auth |
| POST | `/api/rbac/change-role`      | `user.change_role` (super_admin / admin) |
| POST | `/api/rbac/check-permission` | any auth |

Existing endpoints now guarded:

| Endpoint | Permission |
|---|---|
| `GET  /api/backup/export`  | `backup.export`  |
| `POST /api/backup/restore` | `backup.restore` |

More endpoints can be gated by adding `Depends(rbac_require("permission.name"))`
to the signature — no other refactoring needed.

### 1.3 Response Security Headers — `SecurityHeadersMiddleware` (upgraded)

| Header | Value |
|---|---|
| Content-Security-Policy | `default-src 'none'; frame-ancestors 'none'; base-uri 'none'` |
| Strict-Transport-Security | `max-age=63072000; includeSubDomains; preload` |
| X-Frame-Options | `DENY` |
| X-Content-Type-Options | `nosniff` |
| Referrer-Policy | `strict-origin-when-cross-origin` |
| Permissions-Policy | `geolocation=(), microphone=(), camera=(), payment=(), usb=(), autoplay=()` |
| X-Permitted-Cross-Domain-Policies | `none` |
| Cross-Origin-Opener-Policy | `same-origin` |
| Cross-Origin-Resource-Policy | `same-site` |

Server fingerprinting removed at the middleware layer (uvicorn still adds
`Server: uvicorn`; disabling that is a supervisor config item, tracked in
Remaining Gaps).

### 1.4 Request-Size Guard — `RequestSizeLimitMiddleware`

- Default cap: 15 MB (`MAX_REQUEST_MB` env override)
- Returns HTTP 413 immediately, before body is read → prevents payload-based DoS

### 1.5 Env Validator — `backend/security/env_validator.py`

- Fails startup in production if any of `MONGO_URL`, `DB_NAME`, `JWT_SECRET`
  is missing or set to a known placeholder (`CHANGE_ME_…`, `dev-placeholder`,
  etc.).
- Refuses to boot if `JWT_SECRET` < 32 chars in prod.
- Warns (does not fail) in dev sandboxes.
- Auto-detects prod via `APP_ENV=production` OR non-preview `FRONTEND_URL`.

### 1.6 Log Sanitizer — `backend/security/logs.py`

Installed on root + `uvicorn.*` + `fastapi` + `paisabook` loggers.

Redacts:

- `Bearer <token>` / `Authorization: <token>`
- JWTs (`eyJ...` three-segment)
- JSON fields: `password`, `new_password`, `pin`, `otp`, `secret`, `api_key`,
  `access_token`, `refresh_token`, `token_hash`, `jwt_secret`, `totp_secret`
- Cookies (`access_token=`, `refresh_token=`)
- MongoDB URIs with embedded credentials (`mongodb://user:pw@host` → `<user>:<pw>@`)

Never raises — logging failures are silently ignored.

### 1.7 File Upload Validator — `backend/security/files.py`

Ready for any future upload endpoint (invoice logo, receipt scan, avatar).
Refuses:

- 30+ dangerous extensions (`.exe`, `.php`, `.jsp`, `.svg`, `.html`, `.py`, …)
- Files whose magic bytes disagree with the extension (e.g. `.png` that's
  actually a shell script)
- Files > `UPLOAD_MAX_MB` (default 10 MB)
- Empty files, NUL-byte text files

Auto-generates a UUID filename so user input never lands in a filesystem path.

### 1.8 Dependency Upgrades

`pip-audit` before Session 5: **10 known CVEs**
`pip-audit` after Session 5: **0 known CVEs**

Bumps: `fastapi 0.110.1 → 0.141.1`, `starlette 0.37.2 → 1.4.1`,
`pymongo 4.5.0 → 4.17.0`, `motor 3.3.1 → 3.7.x`,
`python-multipart 0.0.9 → 0.0.18`, `requests → 2.32+`.
All were pinned as `>=` (safe minor upgrades) — deployment can pin to
current resolved versions after CI verification.
